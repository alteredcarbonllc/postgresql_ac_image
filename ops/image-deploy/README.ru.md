# Ручное обновление PostgreSQL 16.6 → 16.15

Это расширение существующего runtime v2 на текущем VPS. Оно устанавливает
новую версию контроллера runit и конфигурационного deployer, добавляя команду
`ac-pg-image`. Автоматического обновления production из Woodpecker здесь нет.

## Допущенный образ

- Git revision: `3bc7acbb9e7374e5b178d6deef41b78ac28cab8c`
- Image ID: `3d14d1a5990f2a500fd48979e8f9955c371ceff450905cf1761fbca748b5d0da`
- PostgreSQL: `160015`
- Предыдущий образ: `61ab21d51c403c7f9c5f58720ee5ef9c7893b1cf4cc4f3eadd2c5f1054081fa3`, `160006`

Это намеренно ограниченное обновление. Произвольные SHA и новые major-версии
не принимаются. Для следующего кандидата нужен отдельный review и изменение
списка допущенных образов после испытаний. Новый коммит этого инструмента
может запустить CI и создать другой кандидат, но его наличие не меняет
допущенный здесь SHA.

До этой установки кандидат прошёл на VPS логическое восстановление ролей и
четырёх баз, pg_verifybackup физической копии, восстановление WAL и чтение всех
пользовательских таблиц на физической копии. Проверена штатная остановка.
Физический backup: `/var/backups/ac-postgresql/pre-image-1615.m7CFxw`.
Отчёт: `physical-test.Tpimzw/result.txt`. Это свидетельства ручной проверки,
не автоматический допуск по наличию файла-маркера.

## Установка без перезапуска

Из корня репозитория:

```sh
python3 -m unittest discover -s ops/image-deploy/tests -v
sudo python3 ops/image-deploy/install-v3.py
sudo /usr/local/sbin/ac-pgctl check
sudo /usr/local/sbin/ac-pg-image check 3bc7acbb9e7374e5b178d6deef41b78ac28cab8c
```

Установщик проверяет точное содержимое установленных v2 файлов по сохранённым
`runtime-v2.py` и `config-deploy-v2.py`. При неизвестной версии прекращает
работу. Не обходить эту проверку: сначала сравнить файлы. Сохраняет старые
инструменты и active.json в `/var/lib/ac-postgresql/image-tool-upgrade.*`.
Меняет файлы атомарно, берёт общий lock. Активный манифест не переписывает,
сервисы не перезапускает. Старый `install-v2.py` повторно не запускать.

`check` сверяет защищённую root квитанцию импорта, тег, точный ID, revision label,
платформу и свойства образа. Использует текущий config release и запускает
изолированный тест с временным кластером без production mounts и сети.
Это дополняет уже выполненное испытание физической копии, не заменяет его.

## Развёртывание (короткий перерыв подключений)

После успешной проверки:

```sh
sudo /usr/local/sbin/ac-pg-image deploy 3bc7acbb9e7374e5b178d6deef41b78ac28cab8c
sudo /usr/local/sbin/ac-pgctl check
sudo /usr/local/sbin/ac-pgctl status
```

Сохраняются текущий config commit, PGDATA, log mount, IP/MAC, hostname и
окружение контейнера. Контейнер создаётся по image ID, без `--replace` и
без initdb. Старый останавливается через SIGINT, ждём exit=0; затем он
переименовывается в rollback-контейнер. Новый получает restart=no и runit.

Контроллер проверяет четыре базы, версию для активного image ID, пути
конфигурации, SQL ошибки конфигурации и cgroup supervisor. Существующий
`ac-pg-config` после обновления использует текущий активный образ.

## Откат и границы

При неудаче deploy новый контейнер сначала останавливается. Старый не
запускается, пока остановка нового не подтверждена. SIGKILL не применяется.
Неудачный контейнер сохраняется для диагностики. Старый image и active.json
восстанавливаются, проверяется здоровье. Если откат не удаётся, pending-файл
остаётся и повторный deploy блокируется. Не удалять pending вручную и не
запускать rollback-контейнер напрямую: оба контейнера используют один PGDATA.

Это откат контейнера и образа внутри PostgreSQL 16, не откат данных во времени.
Записи, сделанные приложениями во время проверки нового контейнера, не
отменяются. Физический backup остаётся отдельной копией на момент его создания.
Успешно завершившееся обновление автоматически назад не переключается.

Файлы в `ops/config-deploy` остаются исторической v2-версией. С этого этапа
установленные runtime/deployer поддерживаются в `ops/image-deploy`.
Старые install-v2/runtime installers больше не применять.

Эта поставка сохраняет текущую systemd-обёртку runit и проверку cgroup VPS.
Адаптация установки к Devuan — отдельный этап; этот инструмент ещё не является
универсальным установщиком для обоих init.

## Проверки пакета

Модульные тесты имитируют Podman и runit: проверяют допуск образа, смену
манифеста, сохранение данных/config commit, ошибки после старта, откат,
запрет SIGKILL и неизвестных образов. Git-тесты работают с временным настоящим
репозиторием. Реальный deploy и проверки приложений выполняются на VPS.
